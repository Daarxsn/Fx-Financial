# Pack 8 — API Permission and Security Matrix

**Inventory date:** 22 October 2026  
**Inventory basis:** `src/app/api/**/route.ts` on `main`; 76 route-handler files discovered recursively.  
**Enforcement:** `scripts/validate-pack-8-security.mjs` inventories the route files on every CI run. It checks mutating methods for shared CSRF enforcement or a designated machine-authentication contract, and sensitive reads for an authorization/verified machine gate. The integration suites provide negative-permission, entity-scope, replay/concurrency, session, document and business-workflow tests.

> This is a source-and-test coverage matrix, not a substitute for a third-party penetration test. For routes where legal-entity scoping applies, the current actor’s server-loaded `legalEntityIds` must be enforced before data is returned or a mutation occurs. Shared customer/catalog master-data routes use their resource-specific permissions instead of pretending those records are per-entity. Public health and CSRF bootstrap endpoints intentionally do not require a finance permission.

## Pack 8 checks wired into CI

- `npm run pack8:validate`: verifies the replay-ordering fixes, production origin requirement, shared security headers, private-file integrity controls, input/CSV limits, and protection markers across all discovered API routes.
- `npm run auth:security-test`: full API integration suite, including negative permissions, cross-entity operations, CSRF/session/revocation, idempotency and lifecycle paths.
- `npm run finance:calculation-test`: exact decimal/rounding and DECIMAL(19,4) boundary/overflow checks.
- `npm run documents:unit-test`: PDF integrity and private-storage contracts.
- Pack 7 API/browser and all prior lint/type/build checks remain required; no existing suite is replaced.
